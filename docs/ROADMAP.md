## 1. PROJECT IDENTITY, CURRENT BASELINE (v0.6.0) & STRICT SCOPE GUARDRAILS

### What TestWeave Is
TestWeave is a zero-cloud, local-first CLI and stdio Model Context Protocol (MCP) server (Node.js 20+, pure ESM, TypeScript) that links source files (`paths`) and specifications to manual QA scenarios (Functional and Non-Functional) inside a versioned `test-truth.md` contract at the repository root.
- **5 Codebase Layers:**
  1. `src/cli/` & `src/mcp/`: CLI commands (`init`/`setup`, `update`, `sync`, `doctor`, `scan`, `generate`, `mcp`, `mcp config`, `mcp install`), interactive TTY UI, and stdio MCP server.
  2. `src/engine/`: Contract store (`json testweave` fenced block parser), atomic file writer (`test-truth.md.lock`), Git diff analyzer, local Markdown/source scanner, and `doctor` diagnostics.
  3. `src/integrations/`: 79+ AI coding agent definitions (23 universal `.agents/skills`, 56 dedicated `.claude/skills`, etc.), IDE rule injectors (`<!-- testweave:start -->`), Git pre-push hooks, and QA exporters (`jira`, `xray`, `zephyr`).
  4. `src/schema/`: Authoritative Zod schemas for contracts, modules, tests, and policies.
  5. `src/llm/`: Optional structured-output AI drafting adapters (`openai`, `anthropic`).

### STRICT NON-NEGOTIABLE SCOPE BOUNDARIES (NEVER VIOLATE)
1. **NOT an Automated Test Runner:** Never execute automated tests (Playwright, Jest, Cypress, etc.) or attempt to verify runtime application behavior.
2. **NO Execution Outcome Tracking:** Never store pass/fail/blocked test run logs or historical execution statuses in `test-truth.md`. TestWeave manages *test definitions and code/spec alignment*; downstream tools (Xray, Zephyr, Jira, TestRail) or human checklists handle *execution reporting*.
3. **Zero-Cloud & Deterministic Core:** Core CLI commands (`init`, `sync`, `scan`, `doctor`, `generate`, `diff`, `impact`, `ui`) and MCP tools must work 100% locally without requiring an external cloud SaaS backend or mandatory AI API keys.
4. **Atomic & Non-Destructive Writes:** Always preserve prose outside the `json testweave` code fence in `test-truth.md`, preserve user content outside `<!-- testweave:start -->` markers, and use atomic locking (`test-truth.md.lock`) with Zod validation before writing.

## 2. CORE ARCHITECTURAL STRATEGIES (APPLY ACROSS ALL RELEASES)

### Strategy A: 3-Way Traceability & Spec-Driven "Vibe Coding" (Superpowers SDD)
Support Spec-Driven Development (e.g., Superpowers `docs/superpowers/specs/*.md`, PRDs, System Architecture docs) without creating technical debt or bloating `test-truth.md`:
- **Pointer + Section Slicing (Zero Duplication):** Never copy raw PRD/spec prose into `test-truth.md`. Instead, store workspace-relative file pointers with optional Markdown heading anchors (`#heading-slug`):
  - Top-level `docs: string[]` for global architecture/NFR documents.
  - Module-level `docs` / `specs: string[]` (e.g., `"docs/superpowers/specs/auth-design.md#session-lifecycle"`).
  - Test-level `refs: string[]` (e.g., `["docs/prd/auth.md#ac-1", "PROJ-123"]`).
- **Ignore Ephemeral Implementation Plans:** Track permanent domain specs (`specs/`, `docs/prd/`), not throwaway task plans (`docs/superpowers/plans/YYYY-MM-DD-*.md`).
- **Separate Spec Drift Policy:** Keep code `paths` separate from `docs`/`specs`. Add `policy.docDriftMode: "warn" | "block" | "ignore"` (default `"warn"`). When a linked spec section changes without updating the module's tests, report `stale-spec`. When a linked file or `#heading` anchor is deleted, flag `dead-spec` in `testweave doctor`.

### Strategy B: Radical Token Optimization (~85% Context Reduction)
Do all heavy parsing locally in Node.js (`src/engine/`) for **0 LLM tokens** and send only surgical slices over MCP or `src/llm/`:
1. **Never force agents to read the full `test-truth.md`:** Provide scoped MCP read tools (`get_contract_index`, `get_modules_for_files`, `get_spec_slice`) that return only the target module and the extracted AST Markdown section of the referenced `#heading`.
2. **Never force agents to re-emit unchanged tests:** Provide case-level mutation tools (`upsert_test_case`, `remove_test_case`) alongside `upsert_test_module` so updating `AUTH-001` takes ~15 lines of JSON instead of regenerating the entire module.
3. **Compact Wire Mode (`--compact`):** Strip pretty-print whitespace and omit default-valued fields (`preconditions: []`, `tags: []`, `type: "regression"`) in MCP/LLM payloads while restoring defaults in Zod.
4. **Diff-Scoped Context:** Pass only changed Git diff hunks (`git diff`) for `paths` and `specs` rather than full files when drafting or resolving drift.
